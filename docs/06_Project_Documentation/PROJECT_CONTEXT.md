# 1. Purpose

AI Infrastructure — это долгосрочный инженерный проект по созданию автономной AI-инфраструктуры.

Главная цель проекта:

- хранение открытых AI-моделей;
- долгосрочное архивирование оригинальных моделей;
- локальный запуск AI-моделей;
- автоматизация загрузки и обслуживания;
- создание независимого AI-окружения.


# 1.1 Project Scope

AI Infrastructure сосредоточен на создании автономной локальной AI-инфраструктуры.

Проект НЕ включает:

- обучение собственных AI-моделей;
- разработку новых LLM;
- коммерческие облачные AI-сервисы;
- предоставление публичного AI-хостинга.

Основной фокус проекта:

- долгосрочное хранение AI-моделей;
- локальный запуск AI-моделей;
- автоматизация инфраструктуры;
- независимость от внешних сервисов.



# 2. Project Philosophy

Основной принцип проекта:

Preserve originals.
Automate everything.
Extend, never replace.


Расшифровка:

Preserve originals

Оригинальные модели, версии, метаданные и связанные файлы должны сохраняться без изменений.


Automate everything

Ручные операции должны постепенно заменяться автоматизированными процессами.


Extend, never replace

Новые возможности должны расширять существующую архитектуру, а не ломать её.

# 4. Main Architecture


AI Infrastructure состоит из следующих уровней:


## Knowledge Layer

Документация проекта.

Назначение:

- хранение архитектурных решений;
- описание структуры;
- фиксация текущего состояния;
- передача контекста между рабочими сессиями.


## Archive Layer

Центральное хранилище AI-моделей.

На текущем этапе данный уровень реализуется активным Runtime-проектом архива AI-моделей.

Актуальный Runtime-проект определяется документом CURRENT_STATUS.md.


Назначение:

- загрузка моделей;
- создание архивов;
- хранение метаданных;
- проверка целостности;
- управление реестром.


## Runtime Layer

Будущий уровень локального запуска моделей.


Назначение:

- inference;
- локальные AI-сервисы;
- работа моделей на собственном оборудовании.


## Automation Layer

Будущий уровень автоматизации.


Назначение:

- планировщики;
- синхронизация;
- обновления;
- обслуживание.

Рабочая эталонная модель.


Назначение:

- текущее оборудование;
- практические задачи.


## Class B

- долгосрочный архив;
- будущее оборудование;
- сохранение оригиналов.


# 8. Development Rules


При изменении проекта необходимо:


1. Не ломать существующую архитектуру.

2. Документировать важные решения.

3. Сохранять обратную совместимость.

4. Новые компоненты добавлять расширением.

5. Фиксировать изменения в CHANGELOG.
