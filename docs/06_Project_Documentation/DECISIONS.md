- сохранять историю архитектуры;

# DEC-0002

## Docker Infrastructure

Status:

Accepted


## Decision

Все сервисы проекта запускаются через Docker Compose.


## Rules

Container Manager используется только для мониторинга и визуального контроля.

# DEC-0003

## Modular Architecture

Status:

Accepted


## Decision

Каждый компонент системы реализуется как отдельный модуль.


Примеры:

- HF Client
- Queue Manager
- Download Worker
- Model Registry
- Storage Layer


## Principle

Каждый модуль должен иметь собственную ответственность и минимальные зависимости.

# DEC-0004

## Module API Isolation

Status:

Accepted


## Decision

Runtime-компоненты взаимодействуют только через публичные API модулей.


## Rules

Запрещается:

- прямой доступ к внутренним структурам других модулей;
- зависимость от внутренних деталей реализации.


Цель:

сохранение модульности и возможности дальнейшего расширения системы.

# ADR-0003

## Model Cache Responsibility

Status:

Accepted


## Decision

Model Cache отвечает только за:

- поиск локального архива;
- проверку его целостности;
- возврат пути к валидному архиву.


Model Cache НЕ отвечает за:

- восстановление Registry;
- создание записей Registry;
- синхронизацию Storage и Registry;
- восстановление очереди.


---

## Rationale

Рабочая цепочка загрузки:

```text
Registry
    │
    ▼
Queue
    │
    ▼
Worker
    │
    ▼
Model Cache
```


При потере Registry Worker не получает очередь и не может начать обработку.

Следовательно, восстановление Registry не является ответственностью Model Cache.


Разделение обязанностей соответствует принципу:

Single Responsibility Principle.


---

## Consequence

Восстановление Registry после:

- удаления базы;
- переноса архива;
- восстановления из резервной копии;
- ручного копирования моделей;

реализуется отдельным этапом:

```
HF-0011 — Registry Reconciliation / Recovery
```
